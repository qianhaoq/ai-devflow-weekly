- **[0.163.0](https://github.com/openai/codex/releases/tag/rust-v0.163.0)** — OpenAI Codex · 2026-10-16
  OpenAI Codex 发布 0.163.0。新增 `/config` 偏好搜索、响应中追加指令、`/keymap` 配置 leader key、`/daemon` 重启后台服务等能力，并支持并行运行独立只读工具；Daybreak 对符合条件的账户默认启用。修复了恢复会话时的权限与网络审批、网络代理检查、Windows/WSL 粘贴等问题，并更新了 GPT-6 迁移相关文档。
- **[Upcoming deprecation of selected GitHub Copilot models in mid-November](https://github.blog/changelog/2026-10-15-upcoming-deprecation-of-selected-github-copilot-models-in-mid-november)** — GitHub Copilot · 2026-10-16
  GitHub Copilot 将于 2026 年 11 月 16 日在所有 Copilot 体验（包括 Copilot Chat、内联编辑、ask 与 agent 模式及代码补全）中弃用 Claude Opus 4.8、Claude Opus 5 和 GPT-5.6 Terra 三款模型，官方建议的替代模型分别为 Claude Opus 5.5、Claude Opus 5.5 和 GPT-6.1 Sol 或 GPT-6 Luna。其中 Claude Opus 4.8 对年度计划的个人订阅用户仍保留可用，不适用此次弃用。在默认模型启用设置下，建议的替代模型会自动为 Copilot Enterprise 和 Copilot Business 客户启用，除非管理员关闭了全局默认或明确禁用了该模型。
- **[v2.1.301](https://github.com/anthropics/claude-code/releases/tag/v2.1.301)** — Anthropic Claude Code · 2026-10-16
  Anthropic Claude Code 发布 v2.1.301，新增 `CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS` 环境变量，使无人值守重试模式在用量限制重置时间过远时直接结束请求而非继续等待；同时为 `claude-api` skill 增加 OpenTelemetry 追踪指引，并为 vim 模式加入 `%` 跳转匹配括号动作。该版本还修复了退出时未经询问即删除 `WorktreeCreate` hook 创建的工作树、Grep 与 Glob 在搜索程序异常时误报无匹配、以及 Read 工具将二进制文件按文本读取等问题。
- **[Release v0.25.2](https://github.com/QwenLM/qwen-code/releases/tag/v0.25.2)** — 阿里 Qwen Code · 2026-10-15
  阿里 Qwen Code 发布 v0.25.2，官方说明中无已知破坏性变更。该版本新增多项功能，包括托管代理的邮箱、事件传输与成员消息机制，可选启用的无头 Mods 支持 TypeScript 编写与工具调用拦截，以及 Web Shell 的任务提醒、Excel 只读预览和测试失败浏览器等。
- **[Agentic autofix for code scanning alerts general availability](https://github.blog/changelog/2026-10-15-agentic-autofix-for-code-scanning-alerts-general-availability)** — GitHub Copilot · 2026-10-15
  GitHub Copilot 的代码扫描警报 Agentic autofix 已正式可用，它会像开发者一样探索相关文件、生成修复方案，并重新运行 CodeQL 验证修复能关闭警报后再提交草稿拉取请求供审查。该功能面向 GitHub Enterprise Cloud（含数据驻留）上的 GitHub Code Security 和 GitHub Advanced Security 客户，需企业管理员通过 Advanced Security 策略启用，并消耗 Code Security 预算中的 AI Credits 及 GitHub Actions 分钟数。
- **[HydraFusion updates and new Max option（研究预览）](https://github.blog/changelog/2026-10-14-hydrafusion-updates-and-new-max-option)**（beta/预览） — GitHub · 2026-10-15
  GitHub 更新 HydraFusion，新增 HydraFusion Max 选项，两者均处于研究预览阶段，可在 VS Code、GitHub Copilot 应用和 GitHub Copilot CLI 中使用。HydraFusion 更新了模型池（含 Claude Opus 5.5、GPT-6 Astra、GPT-6.1 Sol、GPT-6 Luna），按阶段调整推理强度，并优化了 Cascade 与 Critique 工作流；HydraFusion Max 沿用相同架构，面向更高要求任务提供前沿能力。两者在启用实验或预览功能后，支持 Copilot Pro、Pro+、Business 和 Enterprise 计划。
- **[v2.1.300](https://github.com/anthropics/claude-code/releases/tag/v2.1.300)** — Anthropic Claude Code · 2026-10-15
  Anthropic Claude Code 发布 v2.1.300，为 mod 的 prompt 装饰新增 `virtualText`，并新增 `prompt.change` mod 钩子、`$.ui.view({ agentId })` 视图切换及 `Text` 的 `dir` 属性以支持从右到左文本。OpenTelemetry 方面，`api_request` 事件新增按生命周期拆分的 `cache_creation_5m_tokens` 与 `cache_creation_1h_tokens`，trace span 加入 GenAI 语义约定属性。该版本还修复了云会话网络设置误报、`/autocompact` 警告、SessionEnd 钩子未运行及多个代理、登录与 diff 视图相关问题。
- **[Gemini 4 Argon in GitHub Copilot](https://github.blog/changelog/2026-10-13-gemini-4-argon-in-github-copilot)** — GitHub Copilot · 2026-10-14
  Google 最新前沿模型 Gemini 4 Argon 已在 GitHub Copilot 中正式可用，面向 Copilot Pro+、Max、Business 和 Enterprise 用户，可在 VS Code、Visual Studio、Copilot CLI、GitHub Copilot coding agent、JetBrains IDE、Xcode、Eclipse 等处的模型选择器中选用，并逐步推送。该模型面向复杂编码、智能体与推理任务，早期测试中在各项编码基准上解决的任务均多于此前 Gemini 模型，在 Copilot CLI 中提升最大，并会在完成前检查边界情况。该模型按用量计费、采用提供商标价。
- **[v2.1.299](https://github.com/anthropics/claude-code/releases/tag/v2.1.299)** — Anthropic Claude Code · 2026-10-14
  Anthropic Claude Code 发布 v2.1.299，新增 `CLAUDE_CODE_DISABLE_FILE_MENTIONS` 环境变量，使 Claude 仅获取 `@` 文件提及的路径而非文件内容；终端新增空闲压缩，闲置约 54 分钟的 200K+ token 会话会在提示缓存过期前被压缩。该版本还新增 `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` 与 `settings.json` 中的 `"idleCompaction": false` 开关（均需 v2.1.290 或更高版本），并修复了多项问题。
- **[Client telemetry user attribution and configurable capture](https://github.blog/changelog/2026-10-12-client-telemetry-user-attribution-and-configurable-capture)** — GitHub Copilot · 2026-10-13
  GitHub Copilot 新增客户端遥测用户归属与可配置采集功能，企业管理员可通过托管设置中的 telemetry.capture.identity 将 Copilot 活动归属到具体用户，而无需收集其提示、响应或工具内容。该设置会向 OpenTelemetry 数据添加 user.name、process.user.name 和 host.name 三个属性，身份采集默认关闭，并与现有的匿名用户标识相互独立。管理员还可分别控制 prompts、responses、toolArguments、toolOutput 和 policyDetail 五个采集类别，所有类别默认关闭，显式托管值优先于本地设置、SDK 配置和环境变量。
- **[Enterprise managed settings enforcement updates](https://github.blog/changelog/2026-10-13-enterprise-managed-settings-enforcement-updates)** — GitHub Copilot · 2026-10-13
  GitHub 为 Copilot 企业托管设置新增强制刷新机制：管理员可通过服务端、MDM 或文件方式设置 forceRemoteSettingsRefresh 为 true，要求 Copilot CLI、VS Code 和 GitHub Copilot 应用在启动时获取最新服务端策略，而非依赖缓存；若无法确认当前策略，客户端将采取失败关闭而非使用过期策略。同时，GitHub 开始为治理类托管设置键逐步加入最低客户端版本要求，首个为 sandbox 键，用户若固定使用旧版本客户端将被强制更新后才能继续使用 Copilot。
- **[Desktop v0.0.46](https://github.com/cline/cline/releases/tag/desktop-v0.0.46)** — Cline · 2026-10-13
  Cline 发布 Desktop v0.0.46，在对话左侧新增提示词大纲，悬停可预览、点击可跳转，并让加载失败的插件在聊天中显示状态行而非静默丢失工具。本次还修复了定时例程排队运行、模型调用失败标记、停机后仅执行最近一次遗漏任务等问题，并刷新模型目录，新增 AI/ML API、LowRouter、Prime Inference 等提供商。
- **[v4.1.24](https://github.com/cline/cline/releases/tag/v4.1.24)** — Cline · 2026-10-13
  Cline 发布 v4.1.24，未选择模型时 Cline 与 OpenRouter 提供方默认使用 Claude Sonnet 5.5，并刷新模型目录，新增 Claude Haiku 5.5 及 AI/ML API、LowRouter、Prime Inference 等提供方，多个提供方的默认模型也随之调整。该版本还修复了关闭推理在部分模型上报 400 错误、MCP 服务器或 hook 提前退出导致扩展宿主崩溃、失效模型 id 的 404 被误显示为登录问题，以及截图等图片虚增 token 估算等问题。
- **[CLI v3.0.71](https://github.com/cline/cline/releases/tag/cli-v3.0.71)** — Cline · 2026-10-13
  Cline 发布 CLI v3.0.71，插件改为在 hub 内加载，不再需要 PATH 中的 JavaScript 运行时，插件加载失败会打印警告并在 `cline config tools --json` 和新增的 `cline hub plugins` 中显示状态与错误，可用 `CLINE_PLUGIN_MODE=sandbox` 保留旧的子进程行为。此版本还让 `--thinking` 在 ACP 模式下生效、`cline hook` 接受 `agent_error` 事件、环境变量中的 provider API key 在启动时即视为已配置，并修复了截图影响 token 估算、自动压缩、计划任务及符号链接规则文件等问题。模型目录同步刷新，新增 AI/ML API、LowRouter、Prime Inference 等 provider，并调整了多个 provider 的默认模型。
- **[SDK v0.0.93](https://github.com/cline/cline/releases/tag/sdk/sdk/v0.0.93)** — Cline · 2026-10-13
  Cline 发布 SDK v0.0.93。插件改为通过每进程单一注册表在进程内加载，编译后的 CLI 及其 hub 不再需要 PATH 上的运行时，同时保留 `CLINE_PLUGIN_MODE=sandbox` 子进程沙箱；注册表为导入、setup、hooks、工具和命令加上超时与错误捕获，并跟踪插件状态，插件失败不再静默丢弃其工具。关闭推理现适用于所有 provider，Gemini 与 Vertex 仅向声明预算的模型发送精确 `thinkingBudget`；`cline` 与 `openrouter` provider 默认模型改为 `anthropic/claude-sonnet-5.5`。此外，token 估算不再按文本费率计算 base64 图片负载，每张图片固定计 1600 tokens；自动压缩改用解析后模型的上下文窗口；计划任务在 `bun:sqlite` 下正确认领队列、以失败记录 provider 错误并取消被新 occurrence 取代的排队 cron；符号链接规则文件现从配置目录加载，`resolveSkillsConfigSearchPaths` 扫描 `.claude/skills`。

- **[Autofix 更名为 Fix comments，Autopilot 更名为 Autofix](https://docs.coderabbit.ai/changelog#2026-10-16)** — CodeRabbit · 2026-10-14
  CodeRabbit 将两项功能更名：原 Autofix 改为 Fix comments，用于一次性修复所选的评审意见（`@coderabbitai fix comments`）；原 Autopilot 改为 Autofix，用于持续修复评审反馈、CodeRabbit 发现的问题和失败的 CI，直到 Coding Agent 的 PR 可以合并。旧命令（含 review 命令）在有限时间内仍可作为别名使用；旧版 CLI 仍使用 autopilot 命令，将在下个 CLI 版本中替换。

## 持续集成

- **[GitHub Actions workflow lockfiles in public preview](https://github.blog/changelog/2026-10-14-github-actions-workflow-lockfiles-in-public-preview)**（beta/预览） — GitHub · 2026-10-14
  GitHub Actions 工作流依赖锁文件（workflow lockfiles）现已进入公开预览，适用于 GitHub Enterprise Cloud、带数据驻留的 GitHub Enterprise Cloud、Team 和 Free 计划。锁文件可让工作流在保留标签或分支引用的同时，运行你所锁定的确切提交，从而防止因标签或分支移动而引入意外或恶意代码；需注意锁定并不判断依赖本身是否安全。可通过 GitHub CLI 的 gh actions-lock 扩展创建和维护锁文件，并支持用 Dependabot 保持锁定的依赖更新。

- **[How Third Moment Research runs 10,000 agents for 36+ hours](https://openai.com/index/third-moment-research)** — OpenAI · 2026-10-14
  OpenAI 介绍了 Third Moment Research 如何借助 Codex、GPT‑6 Astra、GPT‑6 Sol、GPT‑6.1 Sol 与 Daybreak，同时运行 10,000 个 agent，开展持续 36–48 小时的自主研究。该团队用 Codex 定位并修复研究环境中的瓶颈，例如将一年美股订单级数据的回测从约 3 小时缩短到约 3 至 5 分钟，从而减少 token 消耗与上下文污染。其联合创始人表示，GPT‑6.1 Sol 能在数天的计算中保持连贯的研究思路。

  Sourcegraph Amp 于 2026 年 10 月 12 日发布更新，Amp 现在会跟进其开启的 GitHub pull request，评论、审查和 CI 结果都会出现在同一线程中。当 Amp 开启 PR 时，agent 可订阅该 PR 的评论、审查以及最新提交的 CI，失败检查或审查者提问会出现在同一线程中，Amp 已具备处理所需的上下文。该功能依托其新推出的 GitHub Webhooks 一等支持实现，与现有更通用的 webhook 支持不同，新的 GitHub Webhook 集成在 Amp 侧集中处理所有请求，再由用户和 agent 决定是否转发到单个 orb 或每次新建 orb。
